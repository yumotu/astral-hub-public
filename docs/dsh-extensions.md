# DSH 扩展管理

已于2026-11-12部署服务器/网页0.8.12-dsh4，本轮没有发布新安装包。进入关联的 DSH 对话，在上方「设置 → 扩展管理」使用；仅当前登录管理员可管理，外部 DSH 主机须先装星屿扩展桥。验证、备份和回滚见[发行说明](release-0.8.13.md)。

## 技能、原生插件与 MCP

| 类型 | 本轮支持 | 作用范围 |
| --- | --- | --- |
| Skill | 导入/编辑标准 `SKILL.md`，启用、停用、移除、恢复；工具/API 支持附带相对路径文本资源 | 当前主机的工作区 |
| 原生插件 | 固定版本 npm DSH bundle 的安装、升级、启停、移除和同版恢复 | 当前主机的 DSH Profile，可能影响该 Profile 其他会话 |
| MCP | 主机进程 stdio 或 Streamable HTTP，保存配置、连接、工具注册、重新配置、启停和移除恢复 | 当前主机的工作区；注册限定实际 Agent |

技能前置内容例子：

```markdown
---
name: research-helper
description: 阅读项目资料后给出有证据的解释
---
先检查实际资料，区分事实和推测。引用具体文件，缺少依据时说明缺口。
```

技能通过聊天输入框 `/` 的原生技能目录调用。重写正文会保留原资源；工具/API 显式提供 `resources` 才替换资源列表。资源最多32项、单项64 KiB、技能合计512 KiB；不导入压缩包、二进制、私有配置或链接。界面单个 `SKILL.md` 最多60 KB。移除保留可恢复记录。

原生插件填真实 npm 包名和确定版本，例如 `@scope/dsh-plugin@1.2.3`。此示例不是推荐包，也不会自动寻找或安装。必须声明 DSH bundle、兼容固定 Harness。依赖安装不自动批准生命周期/构建脚本；不能借此安装 Pi 包、Git URL 或任意命令。原生版本列表只允许 SDK 核验的更新目标；不提供强制降级按钮。需要构建脚本、图形界面、其他服务或重启的包仍可能不可用，界面以主机实际回执为准。

MCP 主机进程配置使用程序与 JSON 参数数组，凭据放环境变量；HTTP 配置使用地址与请求头，推荐把凭据放请求头。HTTP 非 TLS 仅允许目标主机回环地址。列表/预览隐藏环境变量和请求头的值以及 URL 查询串，但程序参数作为普通配置可见，不要把密钥放参数。重新配置替换旧凭据，需重新填写完整字段。连接检查只发现能力/资源，不调用业务工具；模型调用 MCP 的业务工具按该 MCP 及目标主机的权限执行。

## 预览和恢复

每次更改先冻结名称、版本、作用范围和具体配置预览，五分钟内由同一账号/登录/连接/原生会话确认。取消使预览失效。旧预览与已变化版本冲突时拒绝，不覆盖新修改。管理员可在聊天要求准备扩展更改，模型通过 `assistant.extensions` 查询、`assistant.extension_change` 准备；任务完成后到扩展管理确认。模型没有自行确认、重启或恢复失效授权的工具。

安装不停止正在执行的任务；工作区更改等待对应 Agent 空闲，原生插件更改要求该 Profile 全部 Agent 空闲。临时维护期间不创建新 Agent，已有任务不重放。若主机返回需要重启，保存配置并明确提示，用户另择时重启。

原生插件先安装为停用，再校验声明和受保护项，启用后核验实际 Fiber 加载。更新保留原版本，启动失败时尝试恢复；已停用插件更新后继续停用。主机原有及其他工作区管理的插件不会被当前工作区接管。任意第三方代码仍以 DSH 主机账号执行，管理员应核对真实来源。

MCP 配置替换失败会恢复原配置并报告失败/未知。连接状态以当前原生连接代次读取，不仅凭工具仍登记就显示已连接。网络断线或登录/连接撤销会取消进行中的请求；已经执行但回执丢失时保留未知结果，使用「核对原操作」，不再次点击安装。当前窗口刷新/重开只保存原操作编号，无凭据；关闭浏览器后可重新读取实际目录。

## 接口

统一前缀：`/api/agent/remote/conversations/:id/extensions`。

| 方法/后缀 | 用途 |
| --- | --- |
| `GET /` | 当前工作区目录、原生插件及本登录待确认预览 |
| `GET /skills/:name` | 读取本工作区管理的技能正文/资源 |
| `POST /preview` | 严格 `{change}`；准备具体更改，不执行 |
| `POST /confirm` | `{plan,id}`；一次性确认，ID 绑定固定计划 |
| `POST /discard` | `{plan}`；取消未执行预览 |
| `GET /operations/:id` | 核对原操作，仅限拥有此对话与操作的账号 |

App 使用原 `dsh_actions` 保存操作回执，无新增数据库表；扩展配置在目标主机 Profile 的 `.astral-extensions/` 下加密保存，密钥和状态文件权限600。主机该目录及持久 Profile 应一起备份；不能只保存数据库就宣称可恢复 MCP 凭据。App 重启使未确认预览失效，重新预览；已提交操作不重试。

## 固定运行环境与复验

Harness `0.2.2-rc.1`、Remote `14037e78`、pnpm `11.25.0`。主机使用单独扩展 overlay，不替换原 Profile 的补丁/模型凭据。为新 Profile 补齐官方 `nodeLinker: hoisted` 布局，已有自定义配置不覆盖；自定义依赖布局可能要求重启，不能仅据安装清单推断实际运行版本。

```sh
npm test
npx tsc --noEmit
npm run build
ASTRAL_DSH_EXTENSION_UI=1 node deploy/dsh/extensions-acceptance.mjs
```

最后一条只使用临时合成账号、模型、npm registry 和 MCP，不使用生产密钥或真实用户目录；需要本机固定 Harness QA 依赖、pnpm 和后台 Chrome/Playwright。可用 `ASTRAL_DSH_QA_MODULES`、`ASTRAL_QA_PNPM`、`ASTRAL_QA_PLAYWRIGHT`、`ASTRAL_QA_CHROME` 指定已有安装路径。测试只在用例分组推进隔离 App 时钟，不降低产品频率保护。

构建必须使用完整 `deploy/dsh/Dockerfile`；兼容的 `Dockerfile.workbench` 也已改成完整构建，旧的仅复制 `host.mjs` 配方不包含新依赖。pnpm11使用`pnpm_config_`配置，安装缓存/XDG路径在DSH持久目录，不能退回旧`npm_config_`前缀。本轮完整Linux镜像、隔离60项、实际原生扩展/新进程恢复及生产只读验收通过；测试使用临时真实包，不代表所有第三方插件已验收。原生安装包没有重打。
