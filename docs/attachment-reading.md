# 对话附件读取（0.8.9 开发阶段）

附件原始文件在账号和对话的私有存储中。它不在 Bash 当前目录，不代表 Pi 无法访问；`chat_read` 直接读取校验过的原始字节。服务器、本机和远程电脑共用内容解析模块。

- PDF 默认逐页提取文字；空白或可检测的乱码页使用内置离线中英文 OCR。可显式传 `mode: "ocr"` 重识别。缺少 ToUnicode 并不必然使所有解析失败，工具不据此猜测文件结构。
- 默认每批 3 页，最多 8 页，返回真实 `totalPages`/`nextPage`；继续传 `startPage` 读取后续页。每批文字可继续用 `startLine`/`limit` 分页，不把批次上限当作整份文档上限。
- 图片文字也可离线识别；OCR 返回方法、页码、置信度及警示。文字识别不等同完整图像理解，姓名、数字和重要结论须核对原件。扫描空白、加密、损坏、超时和取消分别返回实际状态，不能声称已经识别成功或原件不存在。
- 支持已有 UTF-8、DOCX 和 XLSX 路径。只读任务和普通成员也能读取、OCR，无需开启 Bash 网络或安装宿主软件。解析在有时限的独立工作线程执行；图片像素和渲染尺寸有界，取消后清理工作目录。
- `chat_save` 将原件复制到当前可修改项目的相对路径，返回真实路径、字节数和 SHA-256，供当前执行器脚本使用。只新建；同内容重试可返回原结果，已有不同内容不覆盖，不修改原附件，不允许只读绕过、私有路径或符号链接。
- 50 MiB 上传上限、200 MiB 电脑原件缓存、账号/对话/租约/本机目录授权与撤销保持。识别结果在当前原生进程内有界缓存（8批/400万字符/10分钟），每次调用仍验证文件和当前授权，不跨账号读取历史。
- `app_functions` 的 `assistant.attachments` 查询当前任务所属对话的真实附件清单；实际字节读取和落盘由上述原生工具执行，不通过管理员凭据绕过鉴权。

运行包固定 unpdf 1.9.1、Tesseract.js 7.0.0、canvas 1.1.0、简体中文/英文语言包 1.0.0、PDF.js 6.4.299 资源及 image-size 2.0.4。渲染器、WASM、语言数据均在安装包/镜像构建时准备，运行时不从 CDN 下载，也不需要系统 root 安装 OCR。图片测试夹具仅含合成中英文文字，不含用户文档。

本阶段验证：375项全量、类型/构建通过；实际本机解析器验证扫描PDF/图片中英文、普通无ToUnicode文本PDF、翻页、损坏文件、取消清理；16 MiB原件落盘/摘要/不覆盖/只读与任务撤销验证通过。Mac/Windows/Linux完整打包及真实用户所报PDF尚未验收，不把合成夹具或本机结果当作已经修复某个未提供文件的证明。当前生产仍为0.8.8。
