# 等待用户回答与中断续接

需要用户提供必需信息、范围或选择时，助手使用内置 `ask_user` 提问，支持直接填写、选择选项及填写其他答案。问题卡片在服务器、本机和远程电脑使用同一组件，页面刷新、切换对话不会代替用户回答。等待答复期间暂停无活动时限，答复只投递给原账号、任务和电脑，保留主输入框草稿。

若应用服务或电脑执行器重启，未确认的原任务保留为中断，已执行的外部操作不会自动重放。可恢复的助手问题仍显示在原消息中；用户明确点击“回答并继续”后，在同一执行位置、项目、对话和权限下创建一次新的续接。先核对保存的进度和工具结果，再使用实际答复继续。原任务仍保留为中断记录，后续任务不会伪装成原任务已完成。

- 每个问题有持久编号；同一答案重复提交只返回同一个续接任务，不再次调用模型。已按另一答案续接时，应在新任务中继续补充。
- 原生上下文及文件授权保留；创建前和执行时重查目录与账号权限。电脑离线则等待原电脑，不转到服务器。
- 只恢复明确来自 `ask_user` 的输入或选择问题；旧版无标记请求、命令/邮件授权、普通插件确认和用户已经停止的任务都不能借此恢复。
- 其他运行中或结果未知的任务仍阻止续接；其他未答问题应重新询问，不能猜测。用户的文字答复不替代发送邮件、消息或执行命令所需的专门授权。
- 原任务中正在追求的目标，只有其原编号与原生记录完全一致且已暂停时，才随这次明确答复恢复。普通新消息、清除后的目标或其他目标不会被自动激活。
- 电脑守护进程崩溃时，断开的 IPC 会停止其等待中的 Pi 工作进程，避免新旧进程同时写原生历史。新任务也会先停止仍在本机记录中的旧工作进程。

续接答案最多 4000 字符，“稍后回答”只收起本次页面中的卡片。旧版电脑执行器需要更新，后端不会把新续接格式降级为重发原始任务。

开发验证区分持久队列/HTTP测试、实际 Pi 进程配合合成模型的守护进程崩溃恢复，以及十二组浏览器布局和真实接口交互。实际模型与正式发行的结果另行记录；模拟器或浏览器验证不等于物理设备验收。
