# 持续目标（0.8.9 开发阶段）

服务器、本机与远程电脑共用固定 `pi-goal@0.1.7` 的目标循环；上游源码、MIT LICENSE、包摘要与逐文件 SHA-256 保存在 `deploy/pi/vendor/pi-goal/`。适配层处理 Pi 1.4 的包名、聊天状态及重启边界，不改上游源文件。没有同时加载第二套目标循环。

只有用户明确要求持续完成并验收一个目标时，助手才调用 `create_goal`。普通问题不自动开启。默认没有 Token 预算，也不添加隐藏迭代上限；用户明确指定时才设置预算。工具保留当前账号、项目、文件、命令和软件操作的实际权限，受限的邮件/选区辅助不会开启目标循环。

- `/long-goal <目标和验收标准>` 开始持续目标。
- `/long-goal status` 查询；`pause` 暂停后续轮次；`clear` 清除目标。这三项通过当前运行时控制投递，即便普通消息选择排队也不会排在目标后面。
- `/long-goal resume` 明确继续已保存目标。先核对进度、原操作和未知结果，不自动重复副作用。
- 模型使用 `get_goal` 检查进度，完成实际验收后使用 `update_goal` 标记完成。缺少必需信息时 `ask_user` 等待真实答复。

目标状态随任务持久保存，以同一紧凑折叠卡片展示真实累计 Token/用时。停止、失败或新工作进程恢复时暂停，普通后续消息不会自动恢复目标。[按目标调度](scheduled-goals.md)可将每次发生绑定到当前执行位置；工作进程/应用重启后的问题续接仍在开发，不能把本阶段测试解释为这些项已经交付。

本阶段验证：371 项回归、类型/构建；真实 Pi SDK 工作进程配合合成 SSE 模型，验证连续轮次、完成、崩溃恢复暂停、显式恢复、运行中暂停及受限工具集合；真实电脑链路验证目标状态回传；独立后台 Chrome 十二组（服务器/电脑、320/375/1280px、浅深色）验证卡片、刷新、答复和无横向溢出。合成模型不是实际 DeepSeek 验收。0.8.9 尚未正式发行，生产仍是 0.8.8。
